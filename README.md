# AIFUYI 官网 — 使用说明

纯静态站点：三个文件（HTML + CSS + 两个 JS），没有构建步骤、没有后端、没有数据库。
把这个目录原样上传到任何支持静态文件的主机就能跑。

> **第一次打开先看 [QUICKSTART.md](QUICKSTART.md)** —— 里面有 VS Code / IntelliJ IDEA 的具体打开方式、逐条改动对照表、以及三处必须同步的联动点。本文件偏技术说明与部署。

```
site/
├─ index.html                     整站唯一页面（单页，锚点分区）
├─ assets/
│  ├─ css/style.css               全部样式（设计变量在文件顶部）
│  ├─ js/rfq.js                   询价单生成器（唯一需要你改数字的文件）
│  ├─ js/site.js                  导航、滚动动画、产品卡跳转
│  ├─ img/                        放本地图片（当前图片仍走 Cloudinary 外链）
│  └─ data/rfq-schema.json        询价数据结构契约（给以后接后端/报价引擎用）
├─ tools/serve.mjs                本地预览服务器（零依赖，node tools/serve.mjs）
├─ .vscode/                       VS Code 任务 / 调试 / 扩展推荐
├─ package.json                   npm run dev
├─ .editorconfig                  缩进 2 空格、LF、UTF-8
├─ QUICKSTART.md                  打开、修改、自测（先看这个）
└─ README.md                      本文件：部署、SEO、校准方法
```

## 1. 本地预览

三种都行，任选其一：

```powershell
cd D:\deepseek\workspace\site

node tools\serve.mjs           # 推荐：零依赖，端口 5173
npm run dev                    # 等价
python -m http.server 5173     # 没有 Node 时
```

浏览器打开 <http://127.0.0.1:5173/>。

也可以直接双击 `index.html`——站点没有任何 `fetch`，`file://` 下功能完整，只是浏览器缓存更顽固，改完要 <kbd>Ctrl</kbd>+<kbd>F5</kbd>。

VS Code：装 Live Server 扩展后在 `index.html` 上右键 → Open with Live Server（端口锚定 5173）。

## 2. 上线前必须改的三件事

### ① 联系方式（`assets/js/rfq.js` 顶部 CONFIG）

```js
var CONFIG = {
  email: 'wenhui452324@gmail.com',   // ← 换成公司邮箱，见下方说明
  whatsapp: '8618777323530',         // 国际格式，只要数字
  ...
```

`index.html` 里也有 3 处硬编码的联系方式（顶部 topbar、`#contact`、页脚、手机底部条），用搜索替换把邮箱和电话统一改掉。

> **关于邮箱**：`wenhui452324@gmail.com` 是个人 Gmail，欧美买家看到会降低信任度——他们判断供应商正规与否，第一眼看的就是域名邮箱。建议先注册 `sales@yhaifuyi.com` 或 `quote@yhaifuyi.com`（你的域名已经买了，企业邮箱服务商几十元/年），把 CONFIG 和页面里全部换掉。这一步对成单率的影响大于本站任何设计细节。

### ② 价格区间的系数（`assets/js/rfq.js` 中 `MATERIAL` / `TOOLING`）

现在的数字是**占位值**，不是从你的成本表算出来的。校准方法见第 4 节。如果你不想公开任何价格，把 `showBand: true` 改成 `false`，摘要卡会自动隐藏价格带，其余功能不受影响。

### ③ 图片

目前全部引用你 Cloudinary 上的原图（`res.cloudinary.com/dvcepymev/...`）。上线前建议下载下来放进 `assets/img/`，改成本地相对路径——这样图片不受第三方账号是否续费、图片是否被删的影响，加载也更快。首屏那张 hero 图建议压到 200 KB 以内。

## 3. 询价是怎么走的

买家在 `#rfq` 里点选 7 组选项（产品 / 螺纹 / 长度 / 座型 / 材质 / 表面处理 / 数量），右侧摘要卡实时拼出一份完整规格，然后有四条出口：

| 按钮 | 实际发生什么 |
|---|---|
| **Send by email** | 调用买家自己的邮件客户端，收件人、主题、正文全部预填好，他只需要**添加图纸附件**再点发送 |
| **WhatsApp** | 打开 `wa.me` 会话，整份规格已预填在输入框里，他加图纸发送 |
| **Copy text** | 纯文本复制到剪贴板，方便他贴进任何地方（包括发给自己同事） |
| **Download as PDF** | 调起浏览器打印，输出一张带编号的规格单（PDF 或纸质），适合展会上用 |

**没有任何数据上传到服务器**，页面也不写 cookie。这是刻意设计：欧美买家对"填表就进你 CRM"有戒心，而"点了直接进我自己的邮箱"没有门槛，转化率明显更高。

### 想让询价也进你自己的系统？

`CONFIG.endpoint` 填上一个地址（Formspree、Basin，或你自己服务器上的一个 PHP 文件），页面就会在买家点发送的**同时**在后台 POST 一份 JSON 给你。JSON 结构见 `assets/data/rfq-schema.json`。

留空则完全客户端运行——买家在邮件里点了取消，你就收不到，这是这套方案的唯一代价。**上线第 1 个月建议留空**，先把邮件/WhatsApp 走顺；等你想做数据统计了再加。

### 询价编号

每次打开页面生成一个，形如 `RFQ-261020-K7B`，同时出现在邮件主题、正文、和打印单上。买家在 WhatsApp 里追问时，你直接搜这个号就能对上。

## 4. 价格区间：为什么这么设计，以及怎么校准

### 为什么给区间而不是报价

- 定制件的成本 80% 由**图纸公差**决定，网站上的选项只决定了另外 20%。给一个精确数字，等于承诺了一个你还不知道能不能做到的价格。
- 但完全不给数字，买家的第一反应是"这家是不是很贵"，然后关掉页面。
- 区间的作用是**筛人**：一个 3,000 件、预算 0.35 美元/件的买家，看到区间自己就走了——省下你来回 5 封邮件的时间。你抱怨的跑单、压价客户，正是被这一条挡在门外的。

所以区间旁边永远跟着 `±25% until we see your drawing` 和「模具费另计」两句话，把它定位成**量级判断**，不是报价。

### 怎么用真实数据校准（重要）

现在的系数是行业经验值，不是你的数字。用你手头**已经成交的 3 个订单**反推，10 分钟能改完：

1. 打开 `assets/js/rfq.js`，找到 `MATERIAL` 表。每个材质有一对 `lo / hi`（美元/件，基准条件：3,000 件、40 mm、球面座、发黑）。
2. 拿你的真实订单：总价 ÷ 数量 = 单件价。把订单条件换算到基准条件（下表是页面用的乘数），反推出该材质的 `lo / hi`。
3. `TOOLING` 表填你实际收的模具费区间（新开搓丝模/冲头）。

页面用的乘数（`PRODUCT` / `SEAT` / `FINISH` / `lengthFactor` / `qtyFactor`）：

| 维度 | 乘数 |
|---|---|
| 数量 | 3,000 → ×1.18 · 5,000 → ×1.06 · 10,000 → ×0.95 · 20,000 → ×0.88 · 50,000 → ×0.80 |
| 长度 | ≤30 mm ×1.00 · 40 ×1.06 · 50 ×1.14 · 60 ×1.24 · 70 ×1.34 · 80 ×1.42 |
| 座型 | 球面 ×1.00 · 平面带垫 ×1.06 · Tuner 花键 ×1.12 |
| 表面 | 发黑 ×1.00 · 锌铝涂层 ×1.10 · 锌镍 ×1.18 · 镀铬 ×1.16 · PVD ×1.22 |
| 产品 | 螺栓 ×1.00 · 螺母 ×0.94 · 螺柱 ×1.06 · 其他 ×1.10 |

改完自己点 3 组配置，看区间是否包住了你的真实成交价。**如果算出来比你实际报价低 30% 以上，一定要上调**——网站报低价、邮件报高价，是最快丢客户的方式。

数量乘数用的是对数插值，所以你填任意数量（比如 6,500 件）也能算，不用只选预设档。低于 3,000 或高于 50,000 会被拦下并提示走人工报价。

## 5. 部署到 www.yhaifuyi.com

### 方案 A：留在现有主机（最省事）

1. **先把现在线上的文件整站备份下载**（这一步别省，覆盖了就没有了）。
2. 通过 FTP 或主机控制面板的文件管理器，把 `index.html` 和 `assets/` 上传到网站根目录，覆盖旧的 `index.html`。
3. 清一下 CDN/浏览器缓存，打开 `www.yhaifuyi.com` 验收。

现有主机如果是国内服务商且没有备案问题，这条路最快。

### 方案 B：Cloudflare Pages（免费 + 全球 CDN + 自动 HTTPS）

对目标市场在美国/德国/意大利/阿联酋的站，Cloudflare 的节点分布比国内虚拟主机好很多，首屏会明显更快。

1. 注册 Cloudflare，把 `yhaifuyi.com` 的 DNS 接过来。
2. Pages → 上传 `site/` 目录（或连 Git 仓库），构建命令留空，输出目录填 `/`。
3. 绑定自定义域名 `www.yhaifuyi.com`，HTTPS 自动签发。

### 无论哪种方案

- **HTTPS 必须有**。买家在地址栏看到"不安全"，转化率直接腰斩。
- 上线后到 Google Search Console 提交一次 `https://www.yhaifuyi.com/`，比任何 SEO 技巧都管用。
- 页面已内置 `Organization` 结构化数据（公司名、地址、联系方式），Google 收录后能在搜索结果里显示得更完整。

## 6. 刻意没做的功能

| 没做 | 原因 |
|---|---|
| **购物车 / 在线下单 / 支付** | 定制件没有单价，只有"按图报价"。购物车要么逼你公开价目表（自杀），要么做成假的（损害信任）。现在的"规格单"就是购物车该有的样子：收集需求，不承诺价格。 |
| **用户注册 / 账户中心** | 你的复购客户一年下单 2–3 次，用邮件就够了。账户系统会带来密码找回、数据合规（GDPR）义务，收益远小于成本。 |
| **在线文件上传** | 上传要存储、要防病毒扫描、要处理 GDPR（买家图纸是商业机密）。让买家把图纸附在自己的邮件里，责任边界最清楚——而且他本来就习惯这么做。 |
| **多语言（德/意/阿）** | 现在做等于维护 4 份文案，而你还没有验证哪句话能转化。等英语版跑出询盘，再翻译转化最好的那几段。 |
| **在线客服弹窗** | 欧美 B2B 买家反感这个，WhatsApp 悬浮按钮（手机端已内置底部操作条）已经覆盖了同样的需求。 |

## 附：改设计时的入口

所有颜色、圆角、最大宽度都在 `assets/css/style.css` 顶部的 `:root` 里：

```css
--accent: #FF5A1F;   /* 主色，橙色 = 工业/工程感，和蓝色系的同行区分开 */
--bg:     #0B0D10;   /* 深色区底色 */
--maxw:   1200px;    /* 内容最大宽度 */
```

改一个变量，全站跟着变。不建议改结构——现在的节奏是「深-浅-深-浅」交替，深色段承担产品和证书的视觉重量，浅色段承担阅读。打乱之后页面会失去顿挫感。
